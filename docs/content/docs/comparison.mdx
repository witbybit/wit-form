Each of these libraries makes different trade-offs. This page tries to show them fairly, including the places where Wit Form is behind. The facts were checked against each library's latest release in October 2026: React Hook Form 7.89 and TanStack Form 1.33. For Wit Form, they describe the current `main` branch.

## At a glance

## Benchmark

Each library renders the same budget table: rows of four number inputs, with a live total under each column. Each one is built the way its docs recommend:

- **Wit Form:** `useField` per cell, and `useFieldArrayColumnWatch` per total.
- **React Hook Form (native inputs):** `register` per cell, and `useWatch` on one column's paths per total.
- **React Hook Form (useController):** the same, with `useController` per cell, as you would for custom inputs.
- **TanStack Form:** `form.Field` per cell, and a `useStore` selector per total.

A script opens each table in Chrome, presses real keys in a cell halfway down, and checks that the column total is right afterwards. **Mount** is the time from rendering the form until the table is on screen. **Keystroke** is the time from a key press until the screen shows the change: the library's update, React's render, and the browser's layout and paint.

What the numbers say:

- **React Hook Form with native inputs is the fastest.** The browser keeps the values, so React does very little. Wit Form takes about 1.6× as long to mount and 3 to 12% longer per keystroke.
- **Among controlled inputs, Wit Form mounts fastest**: about 3× faster than `useController` at 2,000 inputs and 12× at 10,000, and over 10× faster than TanStack Form.
- **Typing costs about the same** in Wit Form and with `useController`, within about 6%. TanStack Form takes 1.3 to 2.4× as long, more as the form grows. At this size, much of each keystroke goes to the browser laying out the large table, which costs the same in every library.

The 4× CPU slowdown stands in for a mid-range laptop or phone. On a fast machine every number is smaller, but the ratios hold. The code is in [`bench/`](https://github.com/witbybit/wit-form/tree/main/bench). Run it with `pnpm --filter wit-form-bench bench`.

## React Hook Form

The most widely used React form library: mature, no dependencies, typed field names, and schema support through resolvers. With native inputs and `register`, typing doesn't re-render React at all.

**Choose it if** you mostly use native inputs, build for React Native, or rely on its ecosystem.

**Where Wit Form differs:**

- Every field is controlled, so custom inputs and UI kits use the same `useField`, with no separate `Controller` path. It mounts large forms several times faster than `useController` (see the [benchmark](#benchmark)).
- Schemas need no extra package, and a form schema's issues land on the matching fields, inside table rows too.
- Hidden fields drop out of the submitted values when they unmount. React Hook Form keeps them unless you set `shouldUnregister`.

## TanStack Form

A typed form library with the deepest type inference of the three: names and values come from `defaultValues`, with no type to write. It runs in several frameworks and has helpers for server actions.

**Choose it if** you need server actions, devtools, or the same form logic outside React.

**Where Wit Form differs:**

- Less API to learn: plain hooks and plain validator functions, and type safety is opt-in with `createFormHooks<Values>()`.
- Table rows keep stable ids through inserts, moves and removals, and one schema drives the errors of the whole form.
- Large forms mount over 10× faster, and typing takes less time (see the [benchmark](#benchmark)).

## When Wit Form is a good fit

- **Large, dynamic forms**: long tables, nested field arrays, forms with hundreds of inputs. Typing re-renders only the cell you're in, with no memoization on your part. See the [Render Performance example](/docs/examples/advanced/render-performance).
- **Forms with many custom inputs** that need to be controlled anyway.
- **Forms validated by a schema**, where one Zod, Valibot or ArkType schema should drive every field's error. See the [Schema Rules example](/docs/examples/validation/schema-rules).
- **Forms with lots of conditional fields**, where hidden fields shouldn't end up in the submitted values.
- **Apps that already use Jotai**, where the extra cost is about 10 kB.
- **Apps moving off react-recoil-form**: it's a drop-in replacement. See [Migrating](/docs/guides/migrating).
