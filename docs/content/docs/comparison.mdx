Each of these libraries makes different trade-offs. This page tries to show them fairly, including the places where Wit Form is behind. The facts were checked against each library's latest release in October 2026: React Hook Form 7.89, TanStack Form 1.33, Formik 2.4.9 and Wit Form 0.1.

## React Hook Form

React Hook Form is the default choice for most React apps, and for good reasons. It's mature, has no dependencies, has typed field names, supports async validation and works with almost every schema library through resolvers. With native inputs and `register`, typing doesn't re-render React at all, which is cheaper than any of the other libraries here, Wit Form included.

**Choose React Hook Form if** you want the most widely used option, you mostly use native inputs, or you rely on schema validation and type-checked field names.

**Where Wit Form differs:**

- Every field is controlled, so custom inputs, date pickers and selects don't need a separate `Controller` path. The same `useField` works for all of them.
- Fields are dropped from the values when they unmount. In React Hook Form they're kept by default, so a hidden conditional field can still be submitted unless you set `shouldUnregister`.
- `extraInfo` stores data such as an option's label or a `File` preview next to a value. In React Hook Form you keep that state yourself.
- `useFieldArrayColumnWatch` subscribes to only some columns of a field array, which helps with running totals over large tables.

## TanStack Form

TanStack Form has the strongest TypeScript story of the four: field names and values are inferred deeply from `defaultValues`. Async validators come with built-in debouncing, Standard Schema works without an adapter, and it has official packages for Next.js server actions and for other frameworks. Re-renders are scoped to each `form.Field`, so typing stays as cheap as it is in Wit Form.

**Choose TanStack Form if** you need type-safe paths, debounced async validation (such as "is this username taken?"), server-side validation, or the same form logic in a framework other than React.

**Where Wit Form differs:**

- Less API to learn: plain hooks and plain validator functions, with no `validators` map and no form-level type parameters.
- Field array rows get stable `rowId`s, so React keys and row state survive inserts and removals without you adding ids to your data.
- Fields are dropped from the values when they unmount. TanStack Form keeps the value and only resets the field's errors.
- A smaller bundle, especially if you already use Jotai.

## Formik

Formik was the most popular form library for years and is still widely installed. Today it's largely unmaintained: the last releases (November 2025) were small React 19 fixes, and the previous one was in April 2024. All state lives in one reducer, so every keystroke re-renders the whole form and every component that reads it. `FastField` helps, but only for simple cases.

**Choose Formik if** you're maintaining an app that already uses it and the forms are small. For new projects, any of the other three is a better fit.

**Moving from Formik to Wit Form** mostly means replacing `<Formik>` with a `FormProvider`, `useFormik` with `useForm`, and `<Field>` with `useField` or Wit Form's `<Field>`. Formik's `validationSchema` has no direct equivalent. Move those rules into field validators, or into `useForm`'s `validate` (see [Validation](/docs/guides/validation)).

## When Wit Form is a good fit

- **Large, dynamic forms**: long tables, nested field arrays, forms with hundreds of inputs. Typing re-renders only the cell you're in, with no memoization on your part. See the [Render Performance example](/docs/examples/advanced/render-performance).
- **Forms with many custom inputs** that need to be controlled anyway.
- **Forms with lots of conditional fields**, where hidden fields shouldn't end up in the submitted values.
- **Apps that already use Jotai**, where the extra cost is about 7 kB.
- **Apps moving off react-recoil-form**: it's a drop-in replacement. See [Migrating](/docs/guides/migrating).

## When to pick something else

Be honest with yourself about these. Wit Form doesn't have them today:

- **Async validation.** Validators are synchronous. To check something on the server, run the request yourself and put the result in the form with `setValue` or a validator that reads it.
- **Schema validation adapters.** You can call Zod or Yup inside a validator, but there's no resolver that maps a whole schema onto your fields.
- **Type-safe field names.** Names are strings and values are typed per field with `useField<Value>`, so a typo in a name isn't a compile error.
- **Form-wide state flags** such as `isValid`, `isSubmitted` or `submitCount`. `formState` has only `isSubmitting`, and dirty tracking is form-wide only (`useIsDirty`).
- **Server actions, SSR helpers, devtools, or frameworks other than React.**
- **A large community.** Wit Form is new. React Hook Form has far more answers, examples and integrations online.

If any of these is a must-have, React Hook Form or TanStack Form will serve you better.
